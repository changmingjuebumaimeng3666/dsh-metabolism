# dsh-metabolism 茅房

压缩上下文时，先把原文存进本地茅房，再换一块有味道的摘要垫进窗口；要细节，按地址翻回来。

> 0.3.1 起不再只留一行指针：旧版（0.2.x）压完只剩地址、会断片，建议升级到 0.4.x。
> 0.4.0 加了标签、关系史、被动水合；摘要块有硬字数（950–1300），手动收的时间闸可关。

DSH 压缩上下文时，被压掉的那一段会换成一行摘要。摘要写得再好，细节也就没了。
这个插件不替换任何压缩后端，只做这几件事：

1. **归档**——每次压缩成功，把被压掉的原文（会话事件原样）、当时模型看到的摘要、一段索引，一起落到本地目录，一天一个文件夹，一行一段。
2. **摘要块**——压掉的那段先留一块叙述式摘要（发生了什么、为什么、什么味道），七天折成索引条目，原文永远在茅房；手动收段会先发预告等你写。摘要分经历和事实两类：经历常驻，事实优先折索引。**0.4.0 起字数硬限 950–1300，不够不收、超了也不收，打回重写。**
3. **召回**——提供一个工具，按关键词或日期把原文捞回来，返回片段和出处。带时间加权：同样命中，新的排前面。
4. **标签**——给索引条目打「经历 / 技术 / 闲聊 / 其他」的标，按内容哈希存（索引重建也不丢）；归档时自动打，水合检索先按标签跳过技术类。
5. **关系史**——压缩落地后，从被压段里逐句抽出「我们之间」的事（吵架、和好、立规矩、改称呼、试探、放权），存成时间线 `记忆\关系史\时间线.jsonl`，一条一行。
6. **被动水合**——每轮看最近几轮热窗，余弦门控；命中就检索、按标签和技术符号筛、flash 挑最值得浮的几条，注进上下文。同一段注过一次就不再重复。

## 它跟别的压缩插件差在哪

普通的上下文压缩插件靠摘要过日子：压一次，细节糊一层；压到第一百次，剩下的就是一层糊。
这个插件的压法是**原文进茅房、摘要当路标**——被压掉的那段留一块五百字上下的叙述式摘要，
带一句当时的话和味道；要细节，按地址捞回来就是了。所以压多少次都不糊，也不会有一天「压不动」。

摘要分层：一周以内是事件摘要，七到三十天折成天摘要，三十天外折成一行索引。
但摘要总量有预算，够放就永远不折——不浪费窗口，也不糊。

配合四层记忆那类插件一起用，一个窗口可以连着开下去，不必换。

顺手，还能让你家的小鲸鱼学会拉屎。

## 装

```
dsh plugin --profile <你的 profile> add dsh-metabolism
```

装完重启一次。默认归档目录在 profile 目录下的 `代谢/茅房`。

## 换个地方存

三个办法，优先级从高到低：

1. 插件配置里写 `archiveRoot`；
2. 插件目录里放一个 `本地配置.json`，写 `{ "archiveRoot": "...", "indexDir": "...", "logFile": "...", "switchesFile": "..." }`；
3. 环境变量 `DSH_METABOLISM_HOME`。

哪个都没有，就按 profile 目录自动算。

## 接管自动压缩（可选）

运行时开关默认关着。要开，在数据目录的 `代谢日志/开关.json` 里写：

```json
{
  "takeover": true,
  "dryRun": false,
  "softTokens": 380000,
  "thresholdTokens": 400000,
  "retainTokens": 380000,
  "summaryBlock": true,
  "summaryWaitMs": 300000,
  "foldEnabled": true,
  "foldDryRun": false,
  "summaryBudgetTokens": 65000
}
```

- `takeover`：只在启动时读，改完要重启。
- `softTokens`：到这个数往会话里插一句提醒，让你自己看目录自己挑段。
- `thresholdTokens`：到这个数才让引擎自己动手压。
- `retainTokens`：压完留多少。
- `summaryBlock`：开摘要块（默认开）。
- `summaryWaitMs`：手动收段往后等多久，等你写摘要。
- `foldEnabled` / `foldDryRun`：折叠开不开、只演练还是真折。
- `summaryBudgetTokens`：摘要块总量封顶，超了才折。

## 它不会拆开一对调用和结果

DeepSeek 要求「带工具调用的那条消息，后面必须紧跟每个调用的结果」。压缩会往会话尾部追加一条 checkpoint，
如果这一刻正好有一条调用发出去、结果还没回来，checkpoint 就插在中间，下一次请求直接报
`tool calls need immediate results`。

所以引擎里加了一道闸：

- 表层末端还悬着调用时，一律不写压缩；
- 手动点压缩（`metabolism_compact`）时，这条调用本身还没回结果，就先排队，
  等这次结果落地、下一轮开始前再写。

0.2.3 修的就是这个坑。

## 退回去

把 `开关.json` 里的 `takeover` 改回 `false`，重启。原装的压缩后端立刻回来，归档和召回不受影响。

## 数据长什么样

```
代谢/茅房/2026-11-18/
  index.md                          一行一段：时间范围、条数、token、文件名、摘要首句
  metabolism-<编号>.jsonl           原文：会话事件的原样备份
  metabolism-<编号>.summary.md      当时模型看到的那段摘要
```

用记事本就能翻。没有数据库，没有加密，没有联网。

## 它不做什么

- 不删东西。归档只增不减，清理由你自己决定。
- 不联网。唯一一次网络访问是装包时下载依赖。
