# 代谢器 · 茅房归档

## 它做什么

DSH 的上下文满了会压缩：把最老的一段对话换成一条摘要，原文就从模型的视野里消失。这个插件在每次压缩**成功之后**，把被压掉的那一段原文原样留一份到硬盘上，并把当时模型读到的摘要一起存下来。

它不改变压缩本身——压哪一段、留多少、摘要怎么写，还是宿主原来那一套。它只负责「压掉的东西不丢」。

## 文件长在哪

```
记忆\茅房\<日期>\
  index.md                 一行一段：时间范围、条数、token、文件名、摘要首句
  18-42-13-c3f1a2.jsonl    原文：宿主会话事件的原样备份，一行一条
  18-42-13-c3f1a2.summary.md 当时模型看到的摘要
```

- `index.md` 是目录，想找「哪天哪一段」先看它。
- `.jsonl` 是原文，搜关键词用（`Select-String`、编辑器全文搜索都行）。
- `.summary.md` 是摘要，跟上下文里留下那条一致。

## 什么时候会落盘

只在那一次压缩**成功**时。失败的尝试只在会话日志里留一条带错误的事件，这里不会留下半份档案。

新压缩的档案按压缩完成的时刻归日，时间范围写的是被压那一段里最早到最晚一条事件的时刻。

## 配置

插件行 `metabolism` 的配置：

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉就只停止归档，不用卸载 |
| `archiveRoot` | `D:\deepseek工作区\记忆\茅房` | 归档根目录，按日期分 |
| `minTokens` | `0` | 被压段小于这个 token 数就不存（挡掉没营养的小压缩） |

## 目前不做的事

- **不写回摘要。** 摘要正文由宿主的压缩后端生成，这一段事件写入之后不能改，所以「摘要尾部附一行原文路径」还做不到。路径只写在 `index.md` 和 `.summary.md` 里。
- **不改压缩策略。** 这个桌面配置里，真正的压缩后端挂在 Agent 预设里（`compaction` 隔离组），不是宿主平面的那一行（`compaction-basic` 被 web-app 层关掉了）。要按自己的预算切段，得整份替换预设的那一组插件，风险大得多，先不做。
- **没有手动清单。** 「列候选段给我挑」那一层要等接管压缩后端之后才能做。

## 怎么确认它在工作

1. 会话文件里出现 `compaction/start`、`compaction/summary`、一条替换用的 `user/message`、`compaction/end`。
2. `记忆\茅房\<当天>\` 多出 jsonl、summary.md，`index.md` 多一行。
3. 宿主日志里有 `metabolism: archived N events ...` 一行。
